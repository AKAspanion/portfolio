# Switch CI and deploys to pnpm

## Why

The developer moved the project from npm to pnpm: `package-lock.json` is gone, `pnpm-lock.yaml` replaces it, and
`packageManager` in `package.json` pins pnpm. `ci.yml` and `deploy.yml` still run `npm ci`, which fails without an npm
lockfile, so every pull request and every deploy would break.

pnpm also ignores npm's `overrides` field. The pins in `package.json` (`minimatch ^11.0.4`, `glob ^14.0.3`) no longer
apply, and the lockfile resolves `minimatch@10.2.6` and `glob@13.0.6`.

The decision is [pnpm is the package manager](../../knowledge/decisions/pnpm.md).

## What changes

- **`.github/workflows/ci.yml`**, both jobs: add `pnpm/action-setup` pinned to
  `73e46992e05b19abd31f2f3c20e0e7370d762115 # v6.1.1` before `actions/setup-node`, with no `version` input, so it reads
  `packageManager`. Then:
  - `setup-node` uses `cache: pnpm`
  - `npm ci` becomes `pnpm install --frozen-lockfile`
  - `npm run <x>` and `npm test` become `pnpm run <x>` and `pnpm test`
  - `npx <x>` becomes `pnpm exec <x>`
  - `npm audit --omit=dev --audit-level=moderate` becomes `pnpm audit --prod --audit-level moderate`
- **`.github/workflows/deploy.yml`**: the same setup steps, then `pnpm install --frozen-lockfile` and `pnpm run build`.
  The configuration check and the Firebase deploy step are unchanged.
- **`pnpm-workspace.yaml`** (new) holds `overrides:` with `minimatch: ^11.0.4` and `glob: ^14.0.3`. The `overrides`
  block leaves `package.json`. `pnpm install` regenerates `pnpm-lock.yaml`, which must then resolve those versions.
- **`.github/dependabot.yml`** stays as it is: Dependabot's `npm` ecosystem covers pnpm lockfiles.
- **Commands elsewhere:** the README, the ga check commands in `.ga/config.json`, and the commands line in `CLAUDE.md`
  switch to `pnpm` and `pnpm exec`.

## Testing

There is no product behaviour to test first. Locally:

- `pnpm install --frozen-lockfile` succeeds on a clean `node_modules`.
- `pnpm why minimatch` and `pnpm why glob` show only the overridden versions.
- `pnpm audit --prod --audit-level moderate` passes.
- The end-of-work checks pass: smoke, type-check and lint, run through pnpm.

The workflows themselves are proven by the first CI run on the pull request: both jobs green.

## Knowledge

- `decisions/pnpm` (new) records the switch and why the overrides moved.
- `operations/run-locally` and `quality/ci` change their commands from npm to pnpm.

## Out of scope

- Changing the pnpm version, the Node version in `.nvmrc`, or any dependency versions other than the two overrides.
- Earlier specs and plans in `docs/`, which record npm commands as they were at the time.
