## Goal

A personal blog on spanion.in for writing about tech, travel or anything else. Anyone can read published posts. The owner writes, publishes and manages them in a web manager on the live site, from any device, with rich content: headings, links, lists, quotes, code, images and embedded video.

Success means the owner can sign in on their phone or laptop, write a post with images, publish it, and share a `/blog/<slug>` link that anyone can open, whose preview shows the post's own title, description and image. Search engines find every published post through the sitemap and see its structured data. The home page must load no slower than it does today.

## What was agreed

| Topic            | Agreed                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Where posts live | Firestore for posts, Firebase Storage for images, in the same Firebase project as Hosting, which is on the Blaze plan          |
| Who writes       | Only a verified Google sign-in with `panditankit1995@gmail.com`, checked in the security rules                                 |
| Editor           | TipTap (WYSIWYG); the body is stored as TipTap JSON and rendered through the same schema, never as stored HTML                 |
| Language         | Each post is written once, in `en` or `hi`, and shown as written. The blog's labels follow the site language                   |
| Ads              | Published post pages and a blog list with posts carry ads. The manager, an empty list and a missing post never do              |
| SEO              | A Cloud Function serves the blog's public URLs, the sitemap and an RSS feed with each page's tags, structured data and article |
| Workflow         | The team's steps: this spec, then a plan, each task test-first                                                                 |

## Out of scope

- Comments, scheduled publishing, search, multiple authors.
- Pages per tag with their own URL: a tag filter stays a query on `/blog` and isn't indexed.
- Cleaning up orphaned images: images removed from a post's body, or uploaded to a post that is never saved, stay in Storage.

## Routes and screens

All blog routes are lazy-loaded. Firebase, TipTap and their styles are imported only from these routes' chunks. The home page's bundle doesn't change, apart from the menu item.

| Route              | Name          | View             | Index                               | Ads                          |
| ------------------ | ------------- | ---------------- | ----------------------------------- | ---------------------------- |
| `/blog`            | `blog`        | `BlogList.vue`   | yes; `noindex, follow` with `?tag=` | once at least one post shows |
| `/blog/:slug`      | `blog-post`   | `BlogPost.vue`   | yes                                 | once the body has rendered   |
| `/blog/manage`     | `blog-manage` | `BlogManage.vue` | noindex                             | never                        |
| `/blog/manage/:id` | `blog-editor` | `BlogEditor.vue` | noindex                             | never                        |

Static `/blog/manage` outranks `/blog/:slug` in Vue Router, and `manage` is a reserved slug, so they can't collide.

Every blog view sets `ui.loaded = true` on mount, as `NotFound.vue` does, so the page chrome shows without the home page's intro. Colours follow the light and dark greys already used in components ([[design-system/tokens]]). Interactive elements follow [[design-system/accessibility]]: real links and buttons, labelled controls and visible focus. Components use `<style scoped>` only ([decisions/scoped-component-styles](../../knowledge/decisions/scoped-component-styles.md)).

### Blog list (`/blog`)

- Published posts, newest `publishedAt` first, 10 at a time, with a **Load more** button while more remain.
- Each card is a link to the post. It shows the cover image (with its alt text), title, date, reading time, tags, language and excerpt.
- Tags are links to `/blog?tag=<tag>`. A tag filter shows a "Posts tagged …" heading and a link that clears it. The `tag` query value is used only as a Firestore equality value, never in HTML or a selector.
- States: loading (skeleton cards), empty ("No posts yet"), error ("Couldn't load posts" with **Try again**), and not configured (see **Configuration**).
- Sets the head through `setHead()` (see **SEO**): title "Blog — Ankit Kumar Pandit", a description, canonical `https://spanion.in/blog`, `noindex, follow` while a tag filter is on, and the RSS alternate link. Restores the previous head on leave.

### Post (`/blog/:slug`)

- Title, date (`publishedAt`), "updated" date when it differs by more than a day, reading time, tags (linked as above), cover image, then the body.
- When the page carries a `#post-data` script for this slug (written by the function, see **SEO**), the post is read from it and Firestore isn't asked. The script is removed once read, so an in-app navigation to another post fetches normally.
- The cover image has `width`, `height` and `fetchpriority="high"`; body images have `width`, `height` and `loading="lazy"`.
- The article element carries the post's `lang`.
- **Share** uses the Web Share API where available and copies the link otherwise, with a confirmation.
- **Back to blog** link.
- Sets the head through `setHead()` with the same title, description, canonical link, Open Graph and Twitter tags the function writes, and restores the previous head on leave. A missing post sets `noindex`.
- A slug that doesn't match a published post shows the not-found content (reusing `NotFound.vue`'s noindex behaviour) under the same URL.
- The body is styled for reading: a comfortable measure (around 70 characters), heading spacing, block quotes, code blocks with syntax highlighting, captioned figures, and responsive 16:9 video embeds.

### Manager (`/blog/manage`)

- Signed out: a short explanation and a **Sign in with Google** button. It uses `signInWithPopup` and falls back to `signInWithRedirect` when the popup is blocked.
- Signed in as anyone but the owner: the account is signed out at once, with the message "This account can't manage the blog."
- Signed in as the owner: a table of every post (title, status, updated date, published date) with **Edit**, **View** for published posts, and **New post**. There's also a **Sign out** button.
- **New post** generates a Firestore document id on the client and opens `/blog/manage/<id>`. Nothing is written until the first save.

### Editor (`/blog/manage/:id`)

- Fields:
  - **Title** (required, at most 200 characters).
  - **Slug**, filled from the title until the owner edits it. It is read-only once the post has a `publishedAt`, with a note saying why.
  - **Excerpt** (required, at most 300 characters).
  - **SEO title** (optional, at most 70 characters) and **SEO description** (optional, at most 160 characters), each with a character counter and a note that empty uses the title or excerpt.
  - **Cover image** with alt text (the alt text is required when there's a cover).
  - **Tags**: up to 10, lower-cased, each 1–30 characters of `a-z`, `0-9` or `-`.
  - **Language**: `en` or `hi`.
  - **Body**.
- Body toolbar: paragraph, H2, H3, bold, italic, strikethrough, inline code, link (with a URL prompt, limited to `https`, `http` and `mailto`), bulleted list, numbered list, quote, code block (with a language picker), image, horizontal rule, YouTube embed, undo and redo. Each button has an `aria-label` and shows its pressed state.
- Images: picking a file resizes it in the browser to at most 2000 px wide and encodes it as WebP. It is then uploaded to `blog/<postId>/<random>.webp`, and its width and height are kept with it (on the cover, and as `width` and `height` attributes of a body figure). Alt text is prompted for, and a caption is optional. The cover uses the same path.
- Actions:
  - **Save** writes the post, keeping its current status.
  - **Publish** validates the post, checks the slug is unique, and sets `status: 'published'`. On the first publish it also sets `publishedAt`.
  - **Unpublish** sets `status: 'draft'` and keeps `publishedAt`, so the slug stays locked.
  - **Delete** asks for confirmation first. It deletes the post document, then every file under `blog/<postId>/`. If removing images fails, the post is still gone and the manager says some images couldn't be removed.
- A post whose slug belongs to another post can't be saved: "Another post already uses this slug."
- Leaving with unsaved changes asks for confirmation, both on route change (`onBeforeRouteLeave`) and on unload (`beforeunload`).
- Errors from Firestore or Storage appear inline and the editor keeps its content. Each failure is logged once to the console with its error code, not the post content.
- An id with no post behind it, once the editor has loaded, is treated as a new post.

### Menu, sitemap

- The menu gets a **Blog** item. `NavItem` gains an optional `route`. An item with a `route` links to that route with a router link instead of scrolling to a home section. `nav.json` gets the item in both locales.
- The nav-item check in `src/__tests__/content.spec.ts` accepts an item with either a known `domId` or a `route` the router resolves to a named, non-404 route.
- The sitemap is generated (see **SEO**), so `public/sitemap.xml` is deleted.
- `public/robots.txt` gains `Disallow: /blog/manage` and keeps its `Sitemap:` line.

## Data

### `posts/{postId}` (Firestore)

| Field            | Type                                            | Rule                                                                                                               |
| ---------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `title`          | string                                          | 1–200 characters                                                                                                   |
| `slug`           | string                                          | matches `^[a-z0-9]+(-[a-z0-9]+)*$`, at most 100 characters, not `manage`                                           |
| `excerpt`        | string                                          | 1–300 characters                                                                                                   |
| `seoTitle`       | string                                          | 0–70 characters; empty means `title`                                                                               |
| `seoDescription` | string                                          | 0–160 characters; empty means `excerpt`                                                                            |
| `cover`          | map `{ url, path, alt, width, height }` or null | `url` is https; `path` is under `blog/<postId>/`; `alt` is 1–200 characters; `width` and `height` are ints 1–10000 |
| `tags`           | list of string                                  | at most 10                                                                                                         |
| `lang`           | string                                          | `en` or `hi`                                                                                                       |
| `content`        | map                                             | TipTap document (`type: 'doc'`)                                                                                    |
| `status`         | string                                          | `draft` or `published`                                                                                             |
| `readingMinutes` | int                                             | at least 1; at 200 words a minute, rounded up                                                                      |
| `createdAt`      | timestamp                                       | set to `request.time` on create; unchanged after                                                                   |
| `updatedAt`      | timestamp                                       | `request.time` on every write                                                                                      |
| `publishedAt`    | timestamp or null                               | null until the first publish; then unchanged                                                                       |

Firestore's 1 MiB document limit caps the body. Images are stored in Storage, not inline, so text alone won't reach it. A save that fails on size shows the error inline.

The public readers use `firebase/firestore/lite`, which has no realtime listeners and is smaller. The manager uses full `firebase/firestore`, `firebase/auth` and `firebase/storage`.

### Indexes (`firestore.indexes.json`)

- `status ==`, `publishedAt desc`: the list.
- `status ==`, `tags array-contains`, `publishedAt desc`: the tag filter.
- Slug lookups (`status ==` and `slug ==`) and the manager's `updatedAt desc` list use single-field indexes.

### Images (Storage)

`blog/<postId>/<random>.webp`, read through its download URL.

## Security rules

The owner check, in both rule files:

```
function isOwner() {
  return request.auth != null
    && request.auth.token.firebase.sign_in_provider == 'google.com'
    && request.auth.token.email == 'panditankit1995@gmail.com'
    && request.auth.token.email_verified == true;
}
```

**Firestore (`firestore.rules`):**

- `posts/{postId}` read: `resource.data.status == 'published' || isOwner()`. The public queries always filter on `status == 'published'`, because rules are not filters: a query that could return a draft is refused.
- create: `isOwner()`, the keys are exactly the fields above, every field rule in the table holds, `createdAt == updatedAt == request.time`, and `publishedAt` is null or `request.time` (with `status == 'published'`).
- update: the same checks, plus:
  - `createdAt` is unchanged and `updatedAt == request.time`.
  - Once `resource.data.publishedAt != null`, `publishedAt` and `slug` are unchanged.
  - A first publish sets `publishedAt == request.time`.
- delete: `isOwner()`.
- Everything else is denied.

**Storage (`storage.rules`):**

- `blog/{postId}/{file}` read: `true`. An image in a draft can be fetched by anyone who has its unguessable download URL. That's accepted.
- write: `isOwner()`, `request.resource.size < 10 * 1024 * 1024` (`MAX_IMAGE_MB = 10`) and `request.resource.contentType.matches('image/.*')`.
- delete: `isOwner()`.
- Everything else is denied.

**The browser:**

- The manager's own owner check is a convenience; the rules are the boundary.
- `renderPost()` builds HTML only through the TipTap schema (`@tiptap/html`, `generateHTML`) with the shared extension list:
  - Link marks keep only `https:`, `http:` and `mailto:` hrefs, and anything else becomes plain text.
  - External links get `target="_blank" rel="noopener noreferrer"`.
  - Images keep only `https:` sources.
  - YouTube embeds keep only video ids from `youtube.com` or `youtu.be` URLs, and are rendered as `https://www.youtube-nocookie.com/embed/<id>`.
- The result is the only `v-html` in the blog.
- The `slug` route parameter and the `tag` query are used only as Firestore equality values.
- The current Content-Security-Policy in `firebase.json` has no `script-src`, `connect-src`, `img-src` or `frame-src`, so Firebase, Google sign-in and YouTube embeds need no header change. The plan must confirm that the popup sign-in works with the headers as they are.

## SEO

[decisions/blog-seo-function](../../knowledge/decisions/blog-seo-function.md) records why. This section says what.

### What each URL carries

The head block of `index.html` is wrapped in `<!-- seo:start -->` and `<!-- seo:end -->`. It holds the title, description, canonical, Open Graph, Twitter and JSON-LD tags. The function replaces everything between the markers, so nothing is duplicated. The home page and `/privacy` keep the block as written.

**A post (`/blog/<slug>`):**

- `<title>`: `<seoTitle or title> — Ankit Kumar Pandit`.
- Meta description: `seoDescription`, or the excerpt cut at a word boundary to at most 160 characters with `…`.
- Canonical: `https://spanion.in/blog/<slug>`.
- Open Graph:
  - `og:type article`, `og:url`, `og:title`, `og:description` and `og:site_name spanion.in`.
  - `og:image` is the cover, with `og:image:width`, `og:image:height` and `og:image:alt`. Without a cover it is `https://spanion.in/images/logo/logo-512x512.webp` at 512 × 512.
  - `og:locale`: `en_IN` or `hi_IN`.
  - `article:published_time`, `article:modified_time`, and one `article:tag` per tag.
- Twitter: `summary_large_image` with a cover, `summary` without; `twitter:title`, `twitter:description`, `twitter:image`.
- JSON-LD:
  - `BlogPosting` with `headline`, `description`, `image`, `datePublished`, `dateModified`, `inLanguage`, `keywords` (the tags), and `mainEntityOfPage` (the canonical URL).
  - `author` and `publisher`: a `Person`, Ankit Kumar Pandit, at `https://spanion.in/`.
  - A `BreadcrumbList`: Home › Blog › the post.
- `<link rel="alternate" type="application/rss+xml" href="https://spanion.in/blog/rss.xml" title="Ankit Kumar Pandit — Blog">`.

**The list (`/blog`):**

- Title "Blog — Ankit Kumar Pandit" and a fixed description.
- Canonical `https://spanion.in/blog`, `og:type website`, Twitter `summary` with the logo image.
- JSON-LD `Blog` with the latest 10 posts as `blogPost` entries (headline and URL), and a `BreadcrumbList`: Home › Blog.
- The RSS alternate link.
- With any `?tag=`, `<meta name="robots" content="noindex, follow">`, and the canonical stays `https://spanion.in/blog`.

**Not found:** a missing or draft slug, a slug that fails `SLUG_PATTERN`, and any deeper `/blog/<a>/<b>` path answer `404`, with the home head block plus `<meta name="robots" content="noindex">`. The SPA then shows its not-found content.

### The function

- **Runtime:** `seo`, a 2nd-gen HTTPS function in `functions/`, on Node 22 in `asia-south1`, with `firebase-admin` for Firestore. It runs with 256 MiB of memory, `maxInstances: 10` and a 30 s timeout.
- **Rewrites in `firebase.json`, in this order:**
  1. `/blog/manage` and `/blog/manage/**` go to `/index.html`. The function never serves the manager.
  2. `/blog`, `/blog/**` and `/sitemap.xml` go to the function `seo` in `asia-south1`.
  3. `**` goes to `/index.html`, as today.
- **Methods:** only `GET` and `HEAD`; anything else answers `405`.
- **The shell:** the function fetches `https://spanion.in/index.html`, a fixed URL, so the page always names the live deploy's JavaScript files.
  - The fetch has a 3 s deadline and stops reading at 256 KB.
  - A good copy is kept in memory for 60 s.
  - If the fetch fails and an earlier copy exists, that copy is used. With none, the function answers `503` with `Retry-After: 30`.
  - A shell without both `seo` markers is treated as a failed fetch.
- **Firestore reads:**
  - Every query filters on `status == 'published'`, because admin reads bypass the security rules.
  - The slug must pass `isValidSlug()` before any query.
  - Each read has a 5 s deadline. When the deadline passes or the read fails, the function answers `200` with the unchanged shell and `Cache-Control: no-store`, so readers still get the SPA and the failure isn't cached. It logs one line with the error code.
- **A found post:**
  - Its tags are written into the head.
  - `#app` gets an `<article>` with the title, date, cover and the `renderPost()` body. Vue replaces it on mount.
  - `<script id="post-data" type="application/json">` holds the post as `BlogPost.vue` reads it.
- **Escaping:**
  - Every text value is HTML-escaped before it's placed in the page.
  - Every URL placed in a tag is an `https:` URL, checked.
  - JSON-LD and `#post-data` are `JSON.stringify` output with `<`, `>`, `&`, U+2028 and U+2029 written as `\u` escapes, so a post can't close the script element.
- **Shared code:** `functions/` bundles `src/util/slug.ts`, `src/util/renderPost.ts`, `src/util/postSchema.ts` and `src/util/seo.ts` with esbuild. `@tiptap/html` resolves to its server build in Node. The browser and the function describe a post with the same code.
- **Caching:**
  - A `200` answers with `Cache-Control: public, max-age=300, s-maxage=600`.
  - A `404` with `public, max-age=60, s-maxage=300`.
  - The fallback shell with `no-store`.
  - `firebase.json`'s `Cache-Control: no-cache` header on `**` must not override these. Its source excludes the function's paths, and the build confirms in the Hosting emulator that the function's header arrives.

### Sitemap and feed

- `/sitemap.xml` (`application/xml; charset=utf-8`):
  - `https://spanion.in/`, `https://spanion.in/privacy` and `https://spanion.in/blog`.
  - Every published post, with `<lastmod>` set to its `updatedAt` date.
  - The list of fixed pages is a constant in `functions/src/sitemap.ts`, with a comment telling the next page with its own route to add itself there.
- `/blog/rss.xml` (`application/rss+xml; charset=utf-8`):
  - An RSS 2.0 channel titled "Ankit Kumar Pandit — Blog", with an `atom:link rel="self"`.
  - The latest 20 published posts. Each item has `title`, `link`, `guid isPermaLink="true"`, `pubDate` (RFC 822), `description` (the excerpt, escaped) and one `category` per tag.

### In the browser

`src/util/head.ts` exports `setHead(meta)`, which returns a function that restores the previous head. It sets the title, description, canonical, robots, Open Graph and Twitter tags, and the RSS link, in the same tags the function writes. The blog views call it so that in-app navigation keeps the head right. JSON-LD is written only by the function: crawlers load each URL fresh.

`src/util/seo.ts` exports the pure helpers both sides use:

- `pageTitle(post)`
- `pageDescription(post)`
- `postHead(post)`
- `listHead({ tag })`
- `postJsonLd(post)`
- `listJsonLd(posts)`

## Ads

[domain/ads-on-content-pages](../../knowledge/domain/ads-on-content-pages.md) governs this section.

- `BlogPost.vue` calls `loadAds()` after the body has rendered (`nextTick` after the post loads).
- `BlogList.vue` calls `loadAds()` once at least one card has rendered.
- `router.afterEach` reloads when it arrives at `not-found`, `blog-manage` or `blog-editor` from another route while `adsLoaded()` is true. It generalises today's `not-found` check to a list of ad-free route names.
- A list that turns out empty, or a post that turns out missing, while `adsLoaded()` is true, reloads the page once. After the reload no ads are loaded, so it can't loop.

## Privacy policy

The privacy policy at `/privacy` must agree with what the site does ([features/privacy-policy](../../knowledge/features/privacy-policy.md)). The blog changes three of its sections, in both languages, and the `UPDATED` date in `PrivacyPolicy.vue` moves to the day the blog ships:

- **What the site stores:** visitors still have no accounts. The only sign-in is the blog manager's, used by the site owner alone. Whatever Firebase keeps in a visitor's browser on blog pages is named, once the build has checked what that is.
- **Ads:** blog posts and the blog list show ads too, not only the home page.
- **Hosting:** blog posts and their images are served from Cloud Firestore, Cloud Storage for Firebase and Cloud Functions for Firebase, Google services that may log each request, including the IP address, under Google's own terms.

`/privacy` stays out of `adFreeRoutes`: as today, it never requests ads and isn't reloaded when they're already loaded.

## Error handling

- **Public reads:** an error state with **Try again**. The failure is logged once to the console with its code.
- **Not configured:** the message above. Nothing is requested.
- **Manager writes and uploads:** an inline message naming the action that failed ("Couldn't save", "Couldn't upload the image"). The editor keeps its content.
- **Permission denied** in the manager: the owner is signed out and sees the sign-in screen with "Your session has ended. Sign in again."
- **Sign-in popup closed by the owner:** nothing happens. A blocked popup falls back to redirect.

## Risks

- **Bundle size:** Firebase and TipTap are large. They must stay out of the home page's chunk. The plan checks the build output for it.
- **Popup sign-in on mobile Safari** sometimes needs the redirect fallback. The redirect needs `authDomain` to work on the site's domain. The default `<project>.firebaseapp.com` works, and the plan confirms it.
- **Cold starts:** the first request after idle waits for the function to start (about a second). The edge cache absorbs most traffic. If it shows in real use, `minInstances: 1` is the fix, at a small monthly cost.
- **Edge cache and the `**` header:** if Hosting's `no-cache` header reached the function's responses, every request would hit the function. The build checks this in the emulator and again with `curl -I` after the first deploy.
- **Deploy order:** the function deploys before hosting, so the new rewrites never point at a missing function. Because the shell is fetched live, a deploy never pairs the function with stale JavaScript file names.
