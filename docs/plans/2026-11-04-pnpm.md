# Switch CI and Deploys to pnpm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:implement-with-subagents by default, or ga:implement. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make CI and the deploy install and run with pnpm, keep the two dependency overrides in force under pnpm,
and switch the project's documented commands to pnpm.

**Architecture:** The lockfile swap from npm to pnpm is already staged on this branch. Task 1 moves the npm
`overrides` into `pnpm-workspace.yaml` and regenerates the lockfile, and commits it with the swap. Task 2 switches
both GitHub Actions workflows to `pnpm/action-setup` and pnpm commands. Task 1 also switches the ga check commands,
and Task 3 the README.

**Tech Stack:** Vue 3 + Vite (TypeScript), pnpm (version pinned by `packageManager` in `package.json`), Node at the
version in `.nvmrc`, GitHub Actions (`.github/workflows/ci.yml`, `.github/workflows/deploy.yml`), Firebase Hosting.

**Spec:** `docs/specs/2026-11-04-pnpm.md`

## Global Constraints

- Every third-party action is pinned to a full commit SHA with its version in a trailing comment, as the workflows
  already do. `pnpm/action-setup` is `73e46992e05b19abd31f2f3c20e0e7370d762115 # v6.1.1`.
- `pnpm/action-setup` gets no `version` input: it reads `packageManager` from `package.json`.
- Don't change the pnpm version, the Node version in `.nvmrc`, or any dependency version other than `minimatch` and
  `glob`.
- Earlier specs and plans in `docs/` keep their npm commands.

## Checkpoints

None (`run.checkpoints: none`).

### Task 1: Keep the overrides under pnpm

**Files:**

- Create: `pnpm-workspace.yaml`
- Modify: `package.json`
- Modify: `pnpm-lock.yaml`
- Delete: `package-lock.json` (already staged)
- Modify: `.ga/config.json`
- Modify: `CLAUDE.md`

**Interfaces:**

- Consumes: the staged lockfile swap (existing).
- Produces: `pnpm-lock.yaml` that `pnpm install --frozen-lockfile` accepts, with the overrides applied, and the ga
  check commands, which the end-of-work checks run:

| Check          | Command                                     |
| -------------- | ------------------------------------------- |
| `typecheck`    | `pnpm run type-check`                       |
| `lint`         | `pnpm run lint`                             |
| `lint-fix`     | `pnpm run format`                           |
| `format-check` | `pnpm exec prettier --check .`              |
| `test`         | `pnpm test`                                 |
| `e2e`          | `pnpm exec vite build && pnpm run test:e2e` |

```yaml
# pnpm-workspace.yaml
overrides:
  minimatch: ^11.0.4
  glob: ^14.0.3
```

**Spec:**

- What changes: "**`pnpm-workspace.yaml`** (new) holds `overrides:` with `minimatch: ^11.0.4` and `glob: ^14.0.3`.
  The `overrides` block leaves `package.json`. `pnpm install` regenerates `pnpm-lock.yaml`, which must then resolve
  those versions."
- What changes: "**Commands elsewhere:** the README, the ga check commands in `.ga/config.json`, and the commands
  line in `CLAUDE.md` switch to `pnpm` and `pnpm exec`."

**Knowledge:** `decisions/pnpm: the overrides live in pnpm-workspace.yaml` (already written with the spec).

**Acceptance:**

- Given the new `pnpm-workspace.yaml`, when `pnpm why minimatch` runs, then every resolved `minimatch` is `11.x` or
  later, and none is `10.2.6`.
- Given the same, when `pnpm why glob` runs, then every resolved `glob` is `14.x` or later, and none is `13.0.6`.
- Given `node_modules` removed, when `pnpm install --frozen-lockfile` runs, then it succeeds without changing
  `pnpm-lock.yaml`.
- Given `package.json`, then it has no top-level `overrides` field, and `packageManager` is unchanged.
- Given the new versions, when `pnpm run lint` and `pnpm run type-check` run, then both pass (ESLint is what pulls in
  `minimatch`).
- Given `ga.mjs workflow show --json`, then each `checks.commands.*` value is the one in the table above.
- Given `CLAUDE.md`, then the **Commands:** line and the end-of-work checks line name the pnpm commands, and nothing
  else in `CLAUDE.md` changes.

- [ ] **Step 1: Confirm the gap.** Run `pnpm why minimatch` and `pnpm why glob`. Expected: `minimatch@10.2.6` and
      `glob@13.0.6` appear, so the npm overrides are not applied.
- [ ] **Step 2: Move the overrides.** Create `pnpm-workspace.yaml` with the block above, and remove the `overrides`
      block from `package.json`, leaving `packageManager` as it is.
- [ ] **Step 3: Regenerate the lockfile.** Run `pnpm install`.
- [ ] **Step 4: Check the overrides apply.** Run `pnpm why minimatch` and `pnpm why glob`. Expected: only the
      overridden versions.
- [ ] **Step 5: Check a frozen install.** Remove `node_modules`, then run `pnpm install --frozen-lockfile`. Expected:
      success, and `git diff --quiet pnpm-lock.yaml` exits 0 after the install.
- [ ] **Step 6: Check the tools that use them.** Run `pnpm run lint`, then `pnpm run type-check`. Expected: both pass.
- [ ] **Step 7: Set the check commands.** For each row of the table, run
      `node "<ga CLI>/scripts/ga.mjs" workflow set checks.commands.<check> "<command>"`, where `<ga CLI>` is the
      plugin path in CLAUDE.md's `ga CLI:` line. If `workflow set` doesn't rewrite the commands in `CLAUDE.md`, edit
      those two lines by hand.
- [ ] **Step 8: Check the commands.** Run `grep -nE "npm (install|run|test)|npx " CLAUDE.md .ga/config.json`.
      Expected: no output.
- [ ] **Step 9: Commit**

```bash
git add pnpm-workspace.yaml package.json pnpm-lock.yaml package-lock.json .ga/config.json CLAUDE.md
git commit -m "Switch to pnpm, move the minimatch and glob overrides into pnpm-workspace.yaml, and run the ga checks with pnpm."
```

### Task 2: Run CI and the deploy with pnpm

**Files:**

- Modify: `.github/workflows/ci.yml`
- Modify: `.github/workflows/deploy.yml`

**Interfaces:**

- Consumes: `pnpm-lock.yaml` and `pnpm-workspace.yaml` from Task 1, and the existing `packageManager` field in
  `package.json`.
- Produces: no interface. Each job that installs dependencies runs these steps in this order:

```yaml
- uses: pnpm/action-setup@73e46992e05b19abd31f2f3c20e0e7370d762115 # v6.1.1
- uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
  with:
    node-version-file: .nvmrc
    cache: pnpm
- run: pnpm install --frozen-lockfile
```

**Spec:**

- What changes: "`setup-node` uses `cache: pnpm`"
- What changes: "`npm ci` becomes `pnpm install --frozen-lockfile`"
- What changes: "`npm run <x>` and `npm test` become `pnpm run <x>` and `pnpm test`"
- What changes: "`npx <x>` becomes `pnpm exec <x>`"
- What changes: "`npm audit --omit=dev --audit-level=moderate` becomes `pnpm audit --prod --audit-level moderate`"
- What changes: "The configuration check and the Firebase deploy step are unchanged."
- What changes: "**`.github/dependabot.yml`** stays as it is"

**Knowledge:** `quality/ci: the CI and deploy jobs set up pnpm with pnpm/action-setup and install with pnpm install --frozen-lockfile; the runtime audit is pnpm audit --prod`.

**Acceptance:**

- Given `ci.yml` and `deploy.yml`, then neither contains `npm ci`, `npm run`, `npm test`, `npm audit`, `npx ` or
  `cache: npm`.
- Given each of the three jobs (`checks`, `e2e`, `deploy`), then `pnpm/action-setup` pinned to
  `73e46992e05b19abd31f2f3c20e0e7370d762115` comes before `actions/setup-node`, with no `version` input.
- Given the `checks` job, then it runs in order: frozen install, `pnpm run lint`, `pnpm run type-check`, `pnpm test`,
  `pnpm exec vite build`, `pnpm audit --prod --audit-level moderate`.
- Given the `e2e` job, then it runs: frozen install, `pnpm exec playwright install --with-deps chromium`,
  `pnpm exec vite build`, `pnpm run test:e2e`.
- Given the `deploy` job, then the configuration check stays before the install, then frozen install,
  `pnpm run build`, and the Firebase step with its inputs unchanged.
- Given the edited files, when each is parsed as YAML (for example with
  `node -e "require('yaml').parse(require('fs').readFileSync('.github/workflows/ci.yml','utf8'))"` if `yaml` is
  installed, or `python3 -c` with PyYAML), then both parse.
- Given the local tree from Task 1, when `pnpm audit --prod --audit-level moderate` runs, then it exits 0.

- [ ] **Step 1: Edit `ci.yml`.** In both jobs, add the `pnpm/action-setup` step before `setup-node`, set
      `cache: pnpm`, and switch every command as the Acceptance cases list.
- [ ] **Step 2: Edit `deploy.yml`.** Add the `pnpm/action-setup` step before `setup-node`, set `cache: pnpm`, and
      switch to `pnpm install --frozen-lockfile` and `pnpm run build`.
- [ ] **Step 3: Check nothing npm is left.** Run
      `grep -nE "npm ci|npm run|npm test|npm audit|npx |cache: npm" .github/workflows/ci.yml .github/workflows/deploy.yml`.
      Expected: no output.
- [ ] **Step 4: Check both files parse** as YAML.
- [ ] **Step 5: Run the audit locally.** Run `pnpm audit --prod --audit-level moderate`. Expected: exit 0.
- [ ] **Step 6: Commit**

```bash
git add .github/workflows/ci.yml .github/workflows/deploy.yml
git commit -m "Run CI and the Firebase deploy with pnpm."
```
